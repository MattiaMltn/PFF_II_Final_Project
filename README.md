# PFF_II_Final_Project 

**Programming in Finance II — Progetto 2.7 — 2026**

## Overview
This platform allows the user to price options using the Binomial Tree CRR model, compute the greeks, visualize the volatility surface over time with a slider and receive a plain language explanation of the result generated by an LLM.

## Module Specifications
 
### Data Layer — `backend/data/`
 
The data layer is the entry point for all market data in the system. No other module
calls Yahoo Finance, FactSet or touches the database directly — everything flows
through this module.
 
When the user selects a ticker, an option type (call/put) and a style
(European/American), the system synchronizes with the market data source —
either Yahoo Finance via `yfinance` or FactSet via API — and updates the local
SQLite database with all available strikes (K) and expirations (T).
These populate the dropdown menus in the dashboard.
 
Once the user selects a specific strike and expiration, the module extracts four
values from the database: spot price (S), implied volatility (σ), bid and ask.
These — together with K, T and the risk-free rate (r) — form the complete input
set for the Pricing Engine. The output of this module is the direct input of the
Pricing Engine: `get_pricing_inputs()` returns exactly `S, K, T, r, sigma, bid, ask`
with no transformation required on the consumer side.
 
In parallel, save_closing.py runs at end of day to snapshot implied volatility across all supported tickers, strikes and expirations. These snapshots accumulate in the database and feed the Volatility Surface module. The daily execution is intended to be scheduled on a VPS via cron job. 
 
**Public interface** — other modules import only from `backend/data/market_data.py`:
 
```python
from backend.data.market_data import get_option_chain, get_pricing_inputs
```
 
`get_option_chain(ticker, option_type)` → populates the UI dropdowns  
`get_pricing_inputs(ticker, expiration, option_type, strike)` → inputs for the Binomial Tree
 
For offline development without live API calls:
 
```python
from backend.data.mock_data import MOCK_CHAIN, MOCK_PRICING_INPUTS
```
 
**Files**
